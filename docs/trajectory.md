# AI 调用轨迹

参考 `D:\project\deepseek-harness\packages\client\ui-trajectory` 的实现思路：底层按会话保留事件和模型请求，前端将它们按时间投影为可选择的记录，并在检查区显示输入、输出、用量和耗时。贾维斯使用现有 `task_events`、`operation_journal` 和 `model_calls` 合成时间线。

模型调用由 `ModelGateway` 在请求开始和结束时记录。带任务 ID 的调用归属任务及其会话；记忆压缩等带会话 ID 的调用直接归属会话。记录内容包括实际提供方、模型、去除凭证的端点、是否流式、温度、输出上限、超时、响应格式、校验 Schema、完成时间、请求 ID、输入输出 token、耗时、错误类型及 HTTP 状态码（若有）。参数以提供方实际发送的请求为准；OpenAI 兼容提供方当前未发送 Schema 或输出上限，因此 Schema 在页面标为本地校验 Schema。成功和校验失败时都保留提供方的原始模型文本；JSON 解析失败时也保留原始文本，便于分析截断和格式错误。服务重启时将未完成记录标为“interrupted”，不再永久显示“running”。

前端顶部“轨迹”按钮切换到当前会话或历史任务的轨迹页。页面按时间列出任务事件、模型调用、工具操作；支持搜索、按类型或异常筛选、加载更早记录与实时刷新。任务步骤会记录开始、暂停、完成或失败及耗时。工具操作展示权限、动作、遮蔽查询参数的目标、授权 ID、状态、错误码和历时；历时包含可能发生的授权等待。操作的原始参数与结果可能包含秘密信息，因此不会返回给轨迹 API。顶部统计来自整个会话或任务范围，不受分页影响。已有任务事件和工具操作可显示，但部署该功能之前的模型请求配置、输入输出和步骤耗时无法回填。

接口：`GET /api/sessions/:sessionId/trajectory?limit=100&offset=0` 和 `GET /api/tasks/:taskId/trajectory?limit=100&offset=0`，返回 `entries`、`hasMore` 和全量 `summary`。事件沿用原有公开投影，模型输入输出最多各保留 30,000 字符，并遮蔽常见 Bearer 密钥和 URL 凭证参数。轨迹保存在本机 SQLite；在已有配置的 `HOST=127.0.0.1` 下仅本机可访问。

当同一会话的新消息明确要求根据上一轮失败、报错、日志或轨迹排查/修复时，规划器会自动读取最近一个 `FAILED`、`BLOCKED` 或 `CANCELLED` 任务的限长诊断证据（任务结果、失败事件、失败模型调用和失败宿主操作）。这份证据会在进入模型前再次脱敏，不要求用户重复粘贴错误码或日志；原始完整轨迹仍只通过上述接口提供给界面。
