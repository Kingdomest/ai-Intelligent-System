# 贾维斯评估反馈与整轮纠正闭环设计

状态：待用户审核。日期：2026-09-24。

## 1. 目标与已确认的边界

用户要的是主 Agent 派发、子 Agent 执行、测试 Agent 验证、评估 Agent 判断后可依据错误继续修正的闭环，而不是“评估失败就报错”，也不是原样重放同一工具。主 Agent 必须根据评估错误判断是否需要重建生成工具：工具本身有可验证的缺陷时停用旧版本并生成新版本；计划、输入、回答或环境问题不归咎于工具，沿用原版本。

整个用户任务共享最多 **5 次纠正重试**。一次重试的单位是完整纠正回合：主 Agent 根据上一轮反馈派发修正任务 → 子 Agent 完成所需工作 → 测试 Agent 验证 → 评估 Agent 给出新结论。首次执行不是纠正重试，因此最多为首次执行加 5 个完整纠正回合。一个回合中即便有多个子任务、测试用例或主 Agent 判断，也只消耗一次；不能为某个子任务或某个工具另开 5 次额度。权限被拒、缺少必需用户信息、证据不确定或宿主副作用不允许安全重放时直接等待或阻塞，不能为凑次数继续执行。

“删除旧工具”指立即停用并从可用能力检索中移除，但保留代码、版本、评估和操作记录，以便审计及恢复判断，不做物理删除。此规则仅适用于模型生成的能力；项目维护的内置基础能力不能由模型自行删除或替换。继续沿用现有权限模式、宿主代理、沙箱、测试闸门、Canary 发布规则和任务 API。

## 2. 当前实现与问题

- `AgentLoop.ensureCapabilities` 在生成工具失败时已有反馈到 `ToolFactory.build` 的局部循环，也会隔离干运行失败的历史生成能力；这部分尚未与用户任务共享纠正回合计数统一。
- `AgentLoop.executeStep` 遇到评估失败主要重新调用原能力，记录事件只有失败代码，没有把具体原因交给规划/实施 Agent 分析。此路径可能用尽局部次数，却没有修正工具或参数。
- 工具结果完成后，最终 `runResponder → runEvaluator` 只进行一次；评估不通过立即返回泛化的 `FAILED`，丢弃回答草稿和具体失败原因。直接回答路径也只有一次评估。
- 2026-09-24 的文件总结任务中，正确桌面文件的读取、三项沙箱用例及一次实际读取验证均通过，失败仅发生于最终回答评估。同一文件相同内容此前成功。这说明不能把该案例归因于读取工具，也不能用重建读取工具掩盖最终回答闭环缺失。
- 现有 `executionCheckpoint` 能保存计划、能力版本和步骤结果；宿主操作日志已记录结果。新闭环必须复用已证实的结果，并在中断恢复时避免重新执行副作用。

## 3. 方案选择

采用“主 Agent 证据驱动路由 + 全任务共享回合预算”。不采用每次失败都重新生成工具：它会废弃正常能力，也无法修复回答错误。不采用仅给最终回答增加五次模型调用：它留着步骤执行与工具故障的同类缺口。不采用每轮从头重跑整个任务：会造成重复文件写入、重复启动应用或重复网络动作。

主 Agent 可选择 `revise_answer`、`revise_plan_or_input`、`rebuild_generated_tool`、`ask_user`、`block`。模型可提出诊断，但不能单凭自由文本判定工具损坏或批准不安全重放；最终路由受确定性证据、能力来源、权限和操作日志约束。对证据不足的故障保留旧工具并明确阻塞或请求信息，而不是猜测后删除。

## 4. 一轮执行与纠正的状态流

1. 首次执行生成计划并绑定能力版本，派发子任务；各子任务可有局部测试与评估，但本轮汇总一个任务级测试结论和任务级评估结论，作为是否继续纠正的依据。
2. 任一评估失败时生成受限的结构化失败记录：失败阶段、代码、简短原因、证据引用、所涉步骤/能力版本、是否可安全修正。测试执行器的确定性失败不能被模型判读覆盖。必须将具体错误反馈给负责修正的 Agent，不仅记录一个“失败”状态。
3. 主 Agent 决定修正对象。若有可安全执行的纠正方案且 `correctionRoundsUsed < 5`，创建唯一回合 ID 并派发下一轮。回合开始只记录 ID 和阶段；完成“子 Agent 工作 → 测试 → 评估”的结论后才将 `correctionRoundsUsed` 加一。计数提交与评估事件须幂等，重启不能重复扣减或免扣；本轮内的多个规划、生成、测试、评估动作不再单独计数。若 Agent 或测试基础设施不可用，保留回合检查点以便恢复或进入 `BLOCKED`，不能无限重开不计数的新回合。
4. 本轮完成后由测试 Agent 检查新产物/实际效果，再由评估 Agent 判断。通过则任务完成；不通过则将本轮错误及尝试摘要带入下一轮。达到五个纠正回合后停止，返回最后失败原因与各轮修正摘要。
5. 测试失败也要形成该回合的可判读结论；若测试证据不足或权限不允许继续，转 `BLOCKED`/等待用户，而不是假装测试通过。对于直接回答或仅修正总结的回合，测试 Agent 检查回答结构、引用可用性和已验证结果覆盖情况，语义事实判断仍由评估 Agent 完成。

并行子任务属于同一用户任务的同一回合。若只有一个子任务失败，下一轮只重做受影响的子任务及其下游依赖，其他已验证结果保留；任务级回合计数仍只加一。新证据若使旧结果失效，主 Agent 必须重新验证相关下游结果，不能盲用旧数据。

## 5. 反馈路由与工具生命周期

| 可确认的故障 | 主 Agent 处理 | 工具状态 |
| --- | --- | --- |
| 最终总结遗漏、表述或事实对应错误，工具结果已验证 | 将失败原因、上版回答和已验证结果交给回答 Agent 重写，再测试、评估 | 原工具不变，不重复读取 |
| 步骤参数/依赖/计划错误 | 将具体字段、步骤和证据反馈给规划或实施 Agent 修正，只重做必要且安全的部分 | 原工具不变 |
| 生成工具的接口、代码、跨输入通用性或确定性测试失败 | 停用确证有缺陷的版本，把测试/运行错误交给实施 Agent 生成同能力键的新版本；从策略、沙箱、测试和评估重新走发布流程 | 旧版 `deprecated`，新版按现有 Canary/active 规则发布 |
| 内置工具失败或故障归因不足 | 保留内置版本，报告具体故障并阻塞或请求用户信息；不让模型绕过基础工具契约 | 不自动替换 |
| 权限拒绝、宿主结果不确定、非幂等副作用可能重放 | 等待用户或 `BLOCKED`，保留日志和失败说明 | 不自动重放或替换 |

“工具故障已确证”要求确定性测试、宿主契约错误、可信的运行错误或针对具体合法输入可复现的输出不符。评估 Agent 仅凭一句自然语言怀疑工具时，主 Agent 先安排只读/隔离验证；不能立即停用。停用与新版本发布按能力键和确切版本执行，检查点不能悄悄把运行中步骤换成另一版本。新候选必须有不同版本号；有宿主权限时先为当前任务 Canary，实际执行和评估均通过后才 active。若新版本失败，旧缺陷版也不自动复活。

## 6. 重放安全与恢复

复用已完成且已验证的工具结果，是纠正总结的默认方式。只有被现有权限策略和操作日志明确判定安全、可重入的宿主操作才可自动重做，例如只读操作；非安全的启动应用、覆盖/删除文件或具有外部副作用的请求不因评估失败而再次执行。需要新的权限时保留原任务审批流程，用户拒绝后不执行。

在现有 SQLite 表内持久化任务级 `correctionRoundsUsed`、当前回合标识、阶段、能力版本绑定、已验证步骤结果和有限的失败摘要；不新增存放附件全文或密钥的事件字段。回合开始与步骤完成使用可恢复的检查点和事件，进程重启后先读取操作日志确认真实状态：已完成且安全的结果复用，进行中或结果不确定的副作用进入 `BLOCKED`，不能靠重启重复提交。历史任务数据须可读，迁移幂等。

反馈到 Agent 的内容可以包含当前任务所必需的已授权结果及上轮回答，但写入事件/API 的诊断只保留脱敏代码和简短原因，不持久化文件全文、密钥、完整命令输出或模型推理文本。UI 显示“第 n/5 轮纠正”、当前修正对象、测试/评估状态，以及最终失败摘要；不把单个 Agent 调用伪装成一个完整回合。

## 7. 终态与用户可见结果

- `COMPLETED`：关键测试与任务级评估通过，回答由已验证结果支持。
- `NEEDS_USER_INPUT` / `WAITING_FOR_APPROVAL`：缺资料或权限时暂停，保留当前回合；用户补充后继续而非无端开启新回合。
- `BLOCKED`：无法验证或继续会造成不安全重放，说明原因、已完成部分和需要用户决定的下一步；不报成功。
- `FAILED`：五个完整纠正回合耗尽，显示最后具体失败原因、已尝试的修正、尚未满足的验收条件和测试汇总。若评估 Agent 未给出可用的具体原因，显示“评估未提供可执行的错误信息”，不能只写“事实核验失败”。

## 8. 验收与测试

1. 文件读取通过后，最终总结第一次被评估拒绝；回答 Agent 接到具体反馈，首个纠正回合修正通过，宿主读取只发生一次，生成工具数不增加。
2. 计划/输入错误导致评估失败时沿用同一工具版本；主 Agent 修改受影响步骤，测试与评估重新给结论。
3. 经确定性证据确认的生成工具缺陷触发旧版停用和新版本生成；旧版不再被检索或调用，新版必须重新通过通用性、沙箱、权限与实际验证。仅模型怀疑或回答错误不会停用工具。
4. 多子任务或多工具的失败共用任务级五次纠正额度；一轮内多次 Agent 调用、多个测试用例和评估不重复扣数。首次执行加五轮纠正仍失败时报告具体原因及尝试摘要。
5. 拒绝审批或不安全重放时没有第二次宿主副作用；任务正确进入等待/阻塞。重启恢复不会重扣回合、不重复执行已确认操作，也不把版本绑定切到未批准新工具。
6. 测试及错误事件脱敏；API 和前端可恢复显示回合进度、测试摘要、失败原因。全量单元、集成、API、前端测试及构建通过。

## 9. 实施边界

本设计改造现有 AgentLoop、Agent 接口、能力注册与任务展示，不引入另一套独立调度平台或对外 MCP 协议。实现计划需先固定“完整回合”的契约与失败分类，再处理反馈路由、工具替换与重放安全，最后接 UI 和恢复测试。当前工作目录没有 Git 元数据，设计文件无法在此处提交 Git；待该项目纳入仓库后再提交。
