# 贾维斯通用能力与任务可靠性设计

状态：待用户审核。日期：2026-09-23。

## 1. 目标与已确认的原则

用户要解决的是跨任务稳定性，不是仅让“打开网易云音乐”这一句话成功。相同操作类型必须复用同一能力和版本；应用名称、文件路径、网址等目标只能作为调用参数，不能写死在能力代码或检索键中。例如 `process.launch` 对网易云音乐和百度网盘使用同一实现，分别传入不同应用参数。未知操作仍允许实施 Agent 生成新工具，但发布前必须证明它能随不同输入改变行为。

继续保留现有任务级权限模式、宿主权限代理、沙箱、测试 Agent、评估 Agent、Canary 和最多 5 次纠正重试。任何模拟宿主结果不能代替本机验收。目标无法唯一识别、权限被拒、实际结果无法观察时，不得报告成功。

## 2. 现状证据与问题边界

- 真实 Ollama 只读复现中，规划输出 `applicationId: {type: "string", value: "cloudmusic"}` 和 `arguments: {type: "array", value: []}`，而不是运行时需要的字符串和字符串数组。生成代码把该对象放进进程参数，触发 `host.process.run` 干运行契约错误。现有 `steps[].input` 是无约束记录，所以结构化输出格式未约束这一层。
- 能力查询用整句 intent 的精确归一化匹配；更换应用名或文件目标会改变 intent。实施 Agent 提示虽说不要写死路径，却没有跨输入的发布测试。
- 当前 Agent Loop 对所有步骤只保存一个选中能力，并为每个所需能力取首个有输入的步骤，故多能力任务可能调错工具。
- 当前进程执行器等待子进程退出并在超时后终止它；长时间运行的 GUI 应用需要独立的“启动并观察”语义，而不是短命令的 `run` 语义。
- 任务库中已有停留在 `CAPABILITY_BUILDING` 的历史任务；启动恢复只选择有已完成宿主操作及检查点的任务，因此无检查点的中断任务会一直显示为进行中。
- 纯问答路径目前返回“无需执行工具”，没有用户所需的答案。现有 Mock 测试主要覆盖理想输入，不能代表真实模型输出质量。

## 3. 范围与方案选择

采用“稳定通用能力 + 受约束的动态扩展”。基础文件操作、应用启动、短命令、网络请求、位置查询由版本化、参数化的内置能力实现；实施 Agent 仅为没有匹配能力类型的需求生成候选。内置不等于绕过权限或验证：它仍经过现有宿主代理、任务审批、实际效果测试和评估。动态候选须通过跨输入通用性测试才能发布。

不采用仅改提示词并继续六次盲重试：现有失败记录和真实模型复现说明提示词不能保证契约。也不取消动态能力：那会背离用户希望系统扩展和复用未知工具的目标。

本设计集中于任务正确性和能力复用。不把未实现的真正并发调度、上下文治理 Agent、对外 MCP 服务或任意应用的自动安装包装成此次交付；这些应另行验收。

## 4. 规划与能力契约

规划结果区分回答、等待用户信息、执行动作三种状态。执行步骤必须有稳定 `capabilityKey`、唯一步骤 ID、依赖步骤 ID 和经过校验的 `input`；任务对象名称不属于 `capabilityKey`。基础键包括 `filesystem.read_text`、`filesystem.write_text`、`filesystem.mkdir`、`filesystem.remove`、`process.launch`、`process.run`、`network.request`、`location.current`。未知能力使用命名空间化的稳定键，并声明可变输入字段与输入/输出 Schema。

例如：

```json
{
  "id": "launch-1",
  "capabilityKey": "process.launch",
  "dependsOn": [],
  "input": { "applicationName": "网易云音乐", "args": [] }
}
```

模型输出首先通过按能力键区分的严格 Schema。字符串、数组和对象不能互换。兼容历史模型时，仅可把形如 `{ "type": "string", "value": "..." }` 的明确包装解开并再次校验；不能根据自然语言猜测路径、命令或权限。缺少真实用户信息进入 `NEEDS_USER_INPUT`；模型重复违反结构契约则返回可理解的模型契约错误，不能把同一错误盲重试五次。纯问答必须给出实际 `answer`，由评估检查后返回，不能用“无需执行工具”冒充答复。

计划验证还需拒绝重复步骤 ID、未知依赖、依赖环、未登记且未声明动态生成的能力键，以及步骤与能力类型不匹配。动态能力键不能包含本次目标值。每一步的能力绑定以键和确切版本保存在检查点中；恢复任务不能借用另一步的能力。历史单能力检查点在可以无歧义映射时继续恢复，其他历史状态安全阻塞。

## 5. 通用能力的生成、检索与发布

能力注册表新增稳定能力键索引，优先按 `capabilityKey + 兼容的输入 Schema + 权限` 查找已激活版本，不再用包含“网易云音乐”等目标的整句 intent 作为唯一检索条件。保留 intent 作为说明和辅助排序，不把用户参数混进能力标识。

基础能力的代码由项目维护且版本固定，只从当次 `input` 读取目标和参数；不因用户第一次请求而生成一份专属代码。未知能力由实施 Agent 生成参数化代码、Manifest 和测试，继续走策略检查、沙箱、测试 Agent、评估 Agent、Canary；有宿主权限的版本首次真实任务通过后才转 active。旧能力数据保留，不能自动把未经跨输入测试的旧版本标记为通用 active。

通用性是执行器的发布闸门，而非提示词承诺。对有目标的宿主能力，执行器在隔离环境中用两个不同的合法目标值运行同一候选，核对宿主调用的 permission、action、target 和相关 arguments 随目标变化；还要测缺失输入和宿主失败。测试 Agent 可设计额外用例和判读脱敏证据，但不能推翻确定性失败。对纯计算能力，需要两个不同输入及可判定的输出断言；不能证明通用性时不得宣称“可跨目标复用”。

## 6. Windows 应用启动语义

`process.run` 保留给需要等待结束的短命令；`process.launch` 用于长期运行的 GUI 应用。只读应用解析器按明确的可执行路径、已注册 App Paths、Start Menu 快捷方式或 PATH 中的候选解析用户给的应用名；得到多个候选或没有可信候选时向用户询问路径或选择，不拼接模型生成的 shell 命令。解析结果包含目标可执行文件、参数和供观察使用的进程标识。

启动器通过宿主权限代理显示并执行确切的命令、参数和工作目录；用户拒绝时零启动。GUI 启动返回已发起状态或 PID，不等待应用退出，不在短命令超时后杀掉刚启动的应用。进程、可见窗口及前台窗口由固定只读观察器在有界时间内核查；仅有“进程创建成功”不能报告任务完成。无法观察或应用仅在后台时按证据返回失败/阻塞，不自动重放可能重复的启动。

## 7. 恢复、错误与界面

任务重启时区分：等待审批、已完成宿主操作可安全续验、不确定宿主操作、尚未执行宿主操作却失去运行中的 Agent。前两者沿现有幂等检查点处理；不确定操作进入 `BLOCKED` 且不重放；最后一种未终结任务明确标记可重新提交/重试，不再无限停在“生成中”。已经终结的历史任务结果不追溯修改，能力代码不删除，迁移须幂等。

界面显示输入校验失败、能力构建失败、测试失败、实际观察失败的具体阶段与可执行下一步。任务查询短暂网络失败时继续有限重试并提示连接问题，不使发送框永久锁住。事件仍只保存脱敏测试摘要；错误诊断可记录字段路径和类型，不保存附件全文、密钥或完整生成命令输出。

## 8. 验收与测试

1. 同一 `process.launch` 版本在两组不同应用参数的干运行中产生不同的正确宿主调用；硬编码首次应用名的候选被拒绝发布。`filesystem.mkdir` 等目标型能力同样跨两个路径测试。
2. 真实模型输出的 `{type,value}` 包装要么被安全归一化并通过类型校验，要么在执行前得到明确错误；对象不能进入 `args: string[]`。无效计划不触发本机操作。
3. 第二次打开另一应用时复用已激活的通用能力版本，不为应用名重新生成同类工具；找不到应用时请求用户信息，而非假报成功。
4. GUI 启动不会因短命令超时被杀；Windows 受控测试应用提供进程、窗口可见和前台证据。当前任务的审批模式照常生效，拒绝时零启动。
5. 多能力 DAG 的每一步调用自己绑定的能力；重启恢复不重复已确认副作用，悬空任务有明确终态或恢复指引。
6. 纯问答返回答案；前端网络暂断后能够恢复查询或显示错误。全量单元、集成、API、前端测试和构建通过。Windows 桌面专项验收在受控本机运行。

## 9. 交付边界

实现顺序先以文件系统与应用启动验证类型规划、跨目标发布闸门和逐步骤绑定，再把同一能力契约覆盖网络、位置与短命令；这些阶段均属于本设计的实施范围，不能用某个具体应用成功替代系统性验收。实现过程保留现有 SQLite 任务和能力数据；若发现历史版本无法证明通用，标记待重新验证而不是删除。由于仓库当前没有 Git 元数据，设计文档无法在此工作区直接提交 Git，待接入仓库后可提交。
